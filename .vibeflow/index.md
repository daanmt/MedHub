## Structure
Single-repo medical residency prep platform. Three layers:
1. **CLI tools** (`tools/`) — ingestion, FSRS queue, auditing, sensors, maintenance
2. **Domain layer** (`app/`) — `engine/` (RAG + topic context), `memory/` (cross-session), `utils/` (db, FSRS)
3. **Agent norms** (`.claude/commands/`, `.claude/agents/`, `.agents/workflows/`, `core/contracts/`) — the markdown protocols that *are* the product surface

Pivot (ROADMAP Linha 8): the agent is the interface. The Streamlit multipage app, its
design system, and `summarize_performance()` were removed — **there is no `streamlit_app.py`,
no page, and no `streamlit` dependency.** Study, review, and performance are skills
(`/revisar`, `/performance`), not screens.

All persistent data lives in `ipub.db` (SQLite, local-only). Clinical knowledge lives in
`resumos/**/*.md`. Project state snapshot in `ESTADO.md`.

## Flashcards (post-reform — parts 1-6 + P3)

- **Write-gate:** every writer (`insert_card_base`, `insert_card_extra`, `recurate_cards`,
  `insert_questao`) passes through `tools/card_checks.py::validar_card()` → `{erros, avisos}`.
  `erros` block the write (empty required field, forbidden encoding, question template,
  answer leaked into the front); `avisos` warn (multi-part, orphan negative, artifact
  context, lost distractor). Covered by `tools/test_writer_gates.py` + `test_card_checks.py`.
- **Priority band:** `app/utils/db.py::get_cards_by_bucket()` serves 4 buckets in order —
  `atrasados` → `erros_frescos` → `hoje` → `novos`, exposed by `tools/fsrs_queue.py`.
  `erros_frescos` = cards born from an error inside `JANELA_FRESH_H = 48`h, capped at
  `CAP_FRESH = 8`; card-base (no `questao_id`) never jumps the queue.
- **Provenance:** `fsrs_revlog` carries `card_version` + `selection_reason` per review;
  `flashcards` carries `quality_source`, `card_version`, `needs_qualitative`, `questao_id`.
  `tools/learning_efficacy.py` slices efficacy by those dimensions (pre-migration rows
  grouped as `pre-P3`). `card_version` is a monotone edit counter — `recurate_cards.py`
  bumps it only on a real field change, preserving FSRS state.
- **FSRS is the reference implementation** (`py-fsrs>=6.3.1`), not a hand-rolled v4.
  `app/utils/fsrs.py` is an adapter (`Scheduler(desired_retention=0.9, learning_steps=(),
  enable_fuzzing=False)`); scheduling spread lives in `fsrs_balance.py`.

## RAG (gold-only)

Single collection `resumos` in `data/chroma/` (ChromaDB `PersistentClient`), embeddings via
Ollama `nomic-embed-text`. `search()` does multi-query Raw + HyDE with a textual fallback and
`max_distance=0.35`. **There is no `search_two_tier()` and no `pdf_raw` collection** — the
two-tier experiment was removed in consolidacao part-2 (~130MB reclaimed); BM25 rerank was
removed in 2026-07-12 as regressive on the medical corpus.

## Memory (2 layers)

`app/memory/` implements what survived of the original 3-layer model:
- **Layer 1 — canonical repo:** `AGENTE.md`, `ESTADO.md`, `ipub.db`, `resumos/`.
- **Layer 3 — long-term / cross-thread:** LangMem (`create_memory_store_manager`) over
  `SQLiteMemoryStore(BaseStore)` → `medhub_memory.db`, table `memory_store`.
- **Layer 2 is gone.** `session_insights` was write-only for months and was removed in
  consolidacao part-3. `inspect.py::load_context()` reads **exactly one** namespace:
  `("medhub", "weak_areas")`, counted per `(area, tema)`. The `profile` /
  `study_preferences` / `workflow_rules` namespaces were ghosts (no writer) and are gone.

## Exams (`core/provas.json`)

A top-level JSON **array** of `{"nome", "data", "tipo"}` (`tipo`: `prova` | `grade`), parsed by
`tools/day_plan.py::carregar_provas()`. Drives the countdown in the day-plan header
("ENAMED em N dias · grade fecha em M dias"). **Display only** — the target pace is still
computed against the *grade*, never the exam date. The parser is tolerant by contract:
missing file / bad JSON / malformed entry → WARN on stderr, returns `[]`, the plan never
breaks. Covered by `tools/test_provas.py`.
